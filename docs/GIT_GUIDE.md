# Git — руководство для Nexus

Версия документа: **v1.1.0**  
Актуально для: **Nexus v1.5.0+**

---

## Введение

Это руководство содержит все команды Git, необходимые для работы с проектом Nexus.  
Здесь нет лишней теории — только то, что реально нужно.

---

### Сборка проекта

Для работы над проектом используются две версии сборки:

**Версия для разработчика (с логами в консоли):**
```bash
go build -o nexus-dev.exe .
```

**Релизная версия (без консоли, запускает браузер):**
```bash
go build -ldflags="-H windowsgui" -o nexus.exe .
```

*Примечание: при первом запуске после переустановки системы не забудьте скачать модель для эмбеддингов `ollama pull nomic-embed-text` и обновить зависимости `go mod tidy`.*

## Базовые команды

- `git status` — проверка состояния репозитория  
- `git add .` — добавление всех изменений в коммит  
- `git add <файл>` — добавление конкретного файла  
- `git commit -m "сообщение"` — создание коммита  
- `git push` — отправка изменений на GitHub  
- `git push -u origin main` — первый пуш в новом репозитории

---

## Работа с тегами (версиями)

- `git tag -a vX.Y.Z -m "описание"` — создание нового тега  
- `git tag` — просмотр всех тегов  
- `git push --tags` — отправка тегов на GitHub  
- `git tag -d vX.Y.Z` — удаление тега локально  
- `git push --delete origin vX.Y.Z` — удаление тега на GitHub

---

## Работа с ветками

- `git checkout -b <ветка>` — создание и переход в новую ветку  
- `git checkout main` — переключение на основную ветку  
- `git branch` — просмотр всех веток  
- `git merge <ветка>` — слияние ветки с текущей  
- `git branch -d <ветка>` — удаление ветки

---

## Откаты и восстановление

- `git checkout -- <файл>` — отмена изменений в файле до последнего коммита  
- `git reset --soft HEAD~1` — отмена последнего коммита (сохраняет изменения)  
- `git reset --hard HEAD~1` — отмена последнего коммита (удаляет изменения)  
- `git checkout <хеш-коммита>` — переход к конкретному коммиту

---

## Просмотр и диагностика

- `git log --oneline` — краткая история коммитов  
- `git log -p` — история с изменениями  
- `git diff <файл>` — что изменилось в файле  
- `git remote -v` — просмотр удалённого репозитория

---

## Связь с GitHub Issues

- `git commit -m "описание, closes #<номер>"` — закрытие Issue при пуше  
- `git commit -m "описание, refs #<номер>"` — упоминание Issue без закрытия

## Автоматизация релизов (CI/CD)

Начиная с Nexus v1.5.0, настроен автоматический процесс оповещения о новых релизах.

### GitHub Actions

При создании тега вида `v*` (например, `v1.5.0`) запускается workflow, который:

1. Извлекает последнюю запись из `CHANGELOG.md`.
2. Отправляет уведомление в Telegram-канал.
3. Публикует пост на стене VK-сообщества.

**Файл workflow:** `.github/workflows/notify.yml`

### Необходимые секреты GitHub

Секреты добавляются в репозитории: `Settings → Secrets and variables → Actions`.

| Секрет | Описание |
|--------|----------|
| `TELEGRAM_TOKEN` | Токен Telegram-бота (получить у @BotFather) |
| `TELEGRAM_CHAT_ID` | ID канала/группы (обычно отрицательное, начинается с -100) |
| `VK_ACCESS_TOKEN` | Токен сообщества VK с правом `wall` |
| `VK_GROUP_ID` | Отрицательный ID группы VK (например, `-240807084`) |
