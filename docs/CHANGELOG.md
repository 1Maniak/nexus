# Changelog — Nexus

Все заметные изменения в проекте «Nexus» документируются здесь.

Формат основан на Keep a Changelog, проект придерживается Semantic Versioning.

## [v1.6.0] - 2026-11-07

Мажорное обновление веб-интерфейса и оптимизация работы на слабом железе.

### Добавлено

- **Веб-интерфейс (`web/`)**: локальный чат в браузере с темной темой. Добавлена анимация загрузки (три прыгающие точки) во время генерации ответа.
- **Веб-сервер (`web.go`)**: обработка POST-запросов от браузера с интеграцией RAG-поиска.
- **Кнопка «Выключить Nexus»**: в веб-интерфейсе появилась кнопка, которая корректно завершает работу всех фоновых процессов (Nexus, llama-server, Ollama) и освобождает порты.
- **Файл конфигурации (`config.json`)**: пути к llama-server и модели вынесены из кода. При отсутствии файла он создается автоматически с дефолтными настройками.
- **Автозапуск браузера (`browser.go`)**: при старте Nexus автоматически открывает страницу `http://localhost:8081`.
- **Очистка процессов (`cleanup.go`)**: при закрытии программы автоматически убивается процесс `llama-server.exe`.

### Изменено

- **Разделение на Dev и Prod версии**: 
  - `nexus-dev.exe` запускается с консолью, открывает вкладки с логами сервисов и браузер.
  - `nexus.exe` собирается с флагом `-H windowsgui`, работает скрыто в фоне и открывает только браузер.
- **Пути к файлам**: база данных, папка `base`, конфиг и веб-интерфейс теперь ищутся относительно расположения самого `.exe` файла. Программа работает при запуске из любой директории.
- **Оптимизация скорости**: сокращен системный промпт, `maxHistoryMessages` уменьшено до 6, `maxRAGResults` до 2. Время ожидания первого токена сократилось с 30 до 5-8 секунд на процессоре Xeon.
- **`launcher.go`**: для запуска сервера в Windows Terminal теперь генерируется временный `.bat` файл (`run_llama.bat`), чтобы избежать проблем с экранированием кавычек.

### Исправлено

- Ошибка `unable to open database file`, возникавшая при запуске не из папки проекта.
- Ошибка `404` при запросе эмбеддингов (требовалось скачать модель `nomic-embed-text` для Ollama).
- Конфликт портов (`bind: Only one usage of each socket address`), возникавший из-за зависших в фоне процессов.

## [v1.5.0] - 2026-12-08

### Добавлено

- Реализован **векторный семантический поиск (RAG)** на основе косинусного сходства вместо полнотекстового FTS. Теперь Nexus ищет по смыслу, а не по точным словам.
- Расширен список ключевых слов для автоматического интернет-поиска: добавлены синонимы для валют, цен, погоды и новостей (`валюта`, `американская`, `европейская`, `сколько стоит`, `цена`, `котировка`).
- Добавлена функция `searchByVector`, которая использует эмбеддинги запроса и вычисляет косинусное сходство с векторами в памяти.
- Увеличен `maxHistoryMessages` с 12 до 20 для более глубокого контекста диалога.
- Увеличен `maxGeneratedTokens` с 400 до 2048 для более развёрнутых ответов.

### Изменено

- Поиск по памяти теперь по умолчанию использует векторный поиск (`searchByVector`), а не FTS.
- Обновлён системный промпт: добавлены указания использовать интернет-поиск для актуальных данных (курсы, погода, новости).

### Исправлено

- Повышена стабильность распознавания валютных запросов — модель теперь получает актуальные данные из интернета, а не выдумывает курс.
- Векторный поиск не заменяет интернет-поиск, а дополняет его: если вопрос не требует актуальных данных, используется RAG; если требует — запускается webSearch.

### Оптимизировано

- Код поиска по памяти теперь использует полный перебор векторов с сортировкой по сходству.

## [v1.0.0] - 2026-07-11

### Добавлено

- Первая рабочая версия «Nexus» - локальный ИИ-помощник с долговременной памятью.
- Клиент на Go (500+ строк кода):
  - Потоковый вывод ответов.
  - Цветовая маркировка (системные сообщения, ошибки).
  - Интерактивный диалог с командой exit для выхода.
- Модель: Qwen2.5-Coder-7B-Instruct (Q5_K_M). Запускается через llama-server (движок llama.cpp).
- Память (RAG):
  - Векторная память через эмбеддинги (Ollama + nomic-embed-text).
  - Поиск по косинусному расстоянию с приоритетом знаний.
  - Сохранение диалогов и знаний в memory.json.
- База знаний:
  - Автоматическая загрузка файлов из папки base.
  - Поддерживаемые форматы: .txt, .md, .go, .json, .pdf, .docx, .csv, .html.
  - Разбивка на чанки и добавление в память.
- Инкрементальное обновление базы знаний:
  - Отслеживание изменений файлов через хеши.
  - Добавление только новых или изменённых файлов.
  - Автоматическое удаление фрагментов удалённых файлов.
  - Состояние хранится в knowledge_state.json.
- Системный промпт:
  - Роль Нексуса: помощник Максима.
  - Примеры диалогов (few-shot).
  - Обязательный русский язык и уважительный стиль.

### Исправлено

- Исправлены ошибки работы с PDF (замена pdf.Open на корректный парсинг).
- Улучшена функция чтения CSV (оптимизирована конкатенация строк).
- Устранены конфликты с Vulkan (возврат к стабильной CPU-версии).

### Оптимизировано

- Параметры запуска llama-server:
  - Контекстное окно: -c 4096 (временно, до апгрейда ПК).
  - Количество потоков: -t 8 для полной загрузки CPU.
  - Отключены --no-mmap и --mlock для стабильности.

## [2.0.0] - 2026-09-28

Мажорное обновление. Nexus стал самодостаточным приложением и получил правильную структуру проекта.

### Добавлено

- **Launcher (`launcher.go`)** — автоматический запуск Ollama и llama-server при старте Nexus.
  - Ollama и llama-server открываются в **одном окне Windows Terminal с двумя вкладками**.
  - Проверка портов: Nexus не дублирует запуск, если сервисы уже работают.
  - Ожидание готовности сервисов с таймаутом.
- **Автоперезапуск в Windows Terminal (`terminal.go`)** — если Nexus запущен в `cmd.exe`, он перезапускается в `wt` и корректно определяет рабочую директорию.
- **Поддержка ANSI-цветов** (`enableANSI()`) — цвета работают без кракозябр в любом терминале Windows.
- **Замер скорости генерации токенов** — после каждого ответа Nexus выводит `Скорость: X ток/с (Y сек, ~Z токенов)`.
- **Константы путей к сервисам**: `ollamaURL`, `llamaURL`, `llamaServer`, `llamaModel`.

### Изменено

- **Структура проекта** приведена в порядок:
  - Документация перенесена в `docs/`.
  - Данные (`nexus_memory.db`, `knowledge_state.json`) перенесены в `data/`.
  - База знаний `base/` перенесена внутрь проекта (`nexus-client/base/`).
  - Все пути в коде обновлены на относительные (`./data/`, `./base`).
- **Пути к БД и базе знаний** теперь корректно определяются относительно папки с exe — Nexus можно запускать двойным кликом.
- **`filepathDir` заменён на стандартный `filepath.Dir`** — меньше кода, меньше багов.

### Исправлено

- Ошибка `unable to open database file (14)` при запуске не из папки проекта.
- Ошибка «Не удается найти llama-server» при запуске через `start` в `cmd.exe` — заголовок окна обёрнут в кавычки, пути с пробелами обрабатываются корректно.
- Кракозябры в консоли — решены через `enableANSI()` и перезапуск в Windows Terminal.
- Дублирование запуска сервисов — добавлена проверка портов.

### Удалено

- Зависимость от `.bat`-файлов для запуска — `nexus.exe` теперь самодостаточен.

### Запланировано

- Разбить `main.go` на модули (`config.go`, `logging.go`, `llm.go`, `memory.go`, `knowledge.go`, `filesystem.go`, `search.go`, `utils.go`).
- Управление Git: коммиты, создание тегов (SemVer), пуш, работа с ветками.
- Автоматическое обновление CHANGELOG.md при релизах.
- Агентный цикл (tool calling / function calling).
- Управление ПК (открытие приложений, клики).
- Голос (STT + TTS).
- Зрение (анализ скриншотов).
- Самообучение через RAG и дообучение.
- Портирование на телефон.
